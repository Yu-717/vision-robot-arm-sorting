# ADR-0001：视觉、空间状态与机械臂执行分层

日期：2026-09-14。

## 状态

- **已确认方向**：用户要求继续使用YOLO，组合垃圾分类、手势/人脸相关任务；三维场景还原按空间定位与抓取理解。
- **已执行**：用户授权建立CodeGraph索引，原始资料保留并新增盘点文档。
- **提出待实现**：将视觉、三维场景、任务策略及执行适配分层。本文不把该方案视为用户对所有技术细节的批准。

## 背景

现有示例用四颜色类别触发固定关节角抓放，未将图像坐标转换成机械臂抓取位姿。机械臂STL和FK/IK库提供了部分起点，但缺少标定和完整关节配置。手势、人脸及语音资源主要是模型或数据文件，尚未集成。

## 方案

YOLO负责目标语义和图像证据；空间模块将观测转换为有时效和误差描述的基座坐标；任务策略决定做什么；执行模块独占机械臂并负责状态、取消与结果验证。三维界面读取共享场景状态。

初始按已知桌面平面验证定位与抓放，随后根据实物高度变化和误差需要扩展深度/多视角。该顺序是开发建议，可随设备事实调整。

## 未决定

YOLO具体版本、分割/检测组合、是否添置深度设备、ROS2或其它消息方式、三维渲染框架、模型训练平台、人员身份识别需求均待确定。现有5机身舵机+夹爪不能预设任意末端6D姿态可达。

## 影响

已有Notebook只能分模块提取，不直接作为后台服务入口。需要先确认模型IO、SDK版本、关节单位和标定，才能从固定点动作升级为空间抓取。增加独立记录与回放后，可在不驱动机械臂时验证识别和任务策略。

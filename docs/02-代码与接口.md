## Arm_Lib 调用面

根据课程和Notebook整理；本地没有该库实现，因此错误码、超时、线程安全和固件差异仍未知。

| 调用 | 已知输入/结果 | 实际语义与未确认点 |
|---|---|---|
| `Arm_Device()` | 无参构造，返回控制对象 | 默认通信设备、初始化副作用未知 |
| `Arm_serial_servo_write(id, angle, time)` | id=1–6；课程角度单位°；time单位ms | 发出单舵机运动命令；返回/运动完成确认未定义 |
| `Arm_serial_servo_write6(s1,...,s6,time)` | 6角度+持续时间ms | 批量设置；是否严格同步及ACK语义待确认 |
| `Arm_serial_servo_read(id)` | 单个角度读数 | 未知读失败/超时的返回值，不能无检查用于3D场景更新 |
| `Arm_RGB_set(r,g,b)` | 示例(50,0,0)等 | 参数完整范围需查SDK，不从示例推定 |
| `Arm_Buzzer_On(delay=255)` | 课程delay=1–50，对应100ms–5s；默认255持续响 | 配套 `Arm_Buzzer_Off()`；需要主动关闭持续蜂鸣 |
| `Arm_Button_Mode(enable)` | 1进入学习，0退出 | 课程称进入时关闭扭矩、退出时打开扭矩；与运动任务互斥 |
| `Arm_Action_Study()` | 无参 | 课程描述记录当前姿态，等价K1，最多20组 |
| `Arm_Read_Action_Num()` | 返回动作组数量 | 读异常语义未知 |
| `Arm_Action_Mode(mode)` | 0停止动作组，1单次，2循环 | 只证明动作组停止接口；不能当成所有运动通用急停 |
| `Arm_Clear_Action()` | 清空动作组 | 课程说明不可恢复；不应由初始化流程自动调用 |

夹爪控制只是对6号舵机写角度：流水线示例60°张开、135°闭合，持续400ms。没有夹持力、接触或抓取成功传感器反馈。

课程称5号舵机90–270°、其余0–180°，但流水线的1号舵机位置出现200°、220°，基础摆动示例又让5号舵机经过0–180°。**这些来源存在冲突，不能拼成统一限位表后直接运行。**必须以实物、固件、SDK及接线校准结果建立设备配置。

## 已有视觉推理数据流

来源：arm_line2/Clamping_block.ipynb，代码单元0。

```text
VideoCapture(0)
  → resize到640×480
  → letterbox到640×640（返回ratio和padding）
  → BGR转RGB，HWC转CHW，float16，除255
  → InferSession(0, 'yolov5s_bs1.om').infer([img])[0]
  → torch Tensor → YOLOv5布局假定的NMS
  → Nx6 [x1,y1,x2,y2,confidence,class_id]
  → 反算至输入图像坐标 → 标框、提取名称
  → 连续3次同名 → 预设关节角抓放
```

- 配置中conf/iou阈值均为0.7，输入目标形状640×640。
- `preprocess_image`实际产物是CHW，未显式新增batch轴。**OM模型实际输入shape/dtype和推理包装器行为必须单独核对**，不能把源码意图当已测模型契约。
- `get_pos()`画出了中心点，但返回的是名称列表`msg`，不向控制层提供位置/朝向/深度；动作始终从`p_a`抓取。
- 类别文件包含Green，但动作分支只有Blue、Yellow、Red。绿色不执行抓放。
- `WARMUP_INDEX=5`只跳过前几次调用并显示文字，没有执行真正的模型预热推理。

## 运动学接口

```cpp
bool dofbot_getFK(const char *urdf_file,
                 vector<double> &joints,
                 vector<double> &currentPos);
bool dofbot_getIK(const char *urdf_file,
                 vector<double> &targetXYZ,
                 vector<double> &targetRPY,
                 vector<double> &outjoints);
```

头文件依赖KDL及kdl_parser；`.so`为AArch64 ELF，不能直接当Windows DLL使用。角度/长度单位、关节数量/顺序、RPY约定、基座/末端定义、失败输出是否可用均未在头文件明确。不要默认它能解任意6D末端姿态，现有机构是5个机身舵机加夹爪。

## 开发前需要处理的代码问题

| 发现 | 后果 | 后续处理 |
|---|---|---|
| 片段依赖其它单元的`Arm/time/ctrl_all_servo/time_1/time_2/time_sleep` | 单文件语法通过仍可能NameError | 以课程完整块建立受控例程，保留原文 |
| `01-step-07.py`含裸行`python3` | AST可解析为名字，Python执行时报未定义 | 这是shell提示混入代码，不作为Python程序入口 |
| Notebook在顶层构造SDK、移动和运行相机循环 | 导入/运行全部即可触发机械动作 | 重构前只静态读取；应用入口与设备动作分离 |
| 未检查`capture.read()`的ret再resize | 相机断流可异常中止 | 分离采集状态、失败停止和finally释放 |
| NMS超时分支使用未定义`LOGGER`；关闭的merge分支引用未定义`box_iou` | 特定路径异常，宽泛except会掩盖原因 | 补分支处理与针对性离线测试；不能拿主路径成功代替覆盖 |
| 无目标时`continue`跳过`i += 1`和画面刷新 | 每10帧节奏失效、画面不更新 | 独立帧计数与UI更新 |
| “连续同色”只比较`msg[0]` | 多物体情况下不代表同一物体稳定 | 引入track_id、时效和空间稳定条件 |
| 执行动作时阻塞视觉循环并大量sleep | 使用旧观测；sleep结束不证明到位或抓到 | 感知/执行分离，状态回读及抓取验证 |
| 没有相机到机械臂坐标变换、避障及取消协议 | 不能扩展成任意位置3D抓取 | 按下一份方案建立定位和执行层 |

# 需求规格：基于计算机视觉的智能机械臂垃圾分拣与管理系统

状态日期 **2026-10-08**，用于第 5 周（10.9）需求审查。按课程《02 需求审查布置》的五项提交物组织：① 做什么 ② 不做什么 ③ 验收指标 ④ 接口契约 ⑤ 已知风险。

数字分两类：**已实测**来自本仓库实机记录（2026-09-18 至 09-29，Atlas 200I DK A2 + Dofbot，证据见[硬件实测](../05-板卡连接与硬件实测.md)）；**目标**尚未验证。实现过程见[探索记录](11-探索记录.md)，资产见[资产清单](09-资产清单.md)。

## ① 做什么

只用**腕部单目相机**完成分拣，并把每次动作记成事件：

```text
相机看到            → 算坐标                  → 臂动            → 抓起并投放        → 记录
11 视角扫描+四类检测   地图码注册+正射图定中心朝向   腕部对齐+逆解      按类别放到目标位     log.jsonl → Web 前端
```

功能分三档：**必做**、**排期内**、**备选**。备选项不进排期，必做与排期内全部完成后才开工。

| 档 | 功能 | 现状 |
|---|---|---|
| **必做** | B1 YOLO 目标检测识别待分拣物体 | 已实机跑通 |
| | B2 机械臂精准抓取、定点投放 | 已实机跑通（投到地图码位） |
| | B3 Web 前端实时记录分拣作业全量运行日志 | **尚未开始** |
| | B4 兜底机制（课程 F4） | 机制已实现，待量化 |
| | B5 实体容器投放：四类各一个真实筐，替代地图码位 | 已决定采购，**尚未到货** |
| **排期内** | Web 与设备联动：W1 三种作业模式 · W2 控制面板 · W3 记录导出 · W4 定时启动 · W5 声光反馈 · W6 舵机堵转保护 | 均未开始；W6 的回读核对已有 |
| | 交互与平台外：E1 手势+表情交互 · E7 语音控制 · E8 多端访问 | 均未开始 |
| | 不改抓取模型的视觉扩展：E3 容器溢满检测 · E5 就近优先抓取 · E6 未知物体告警 | 均未开始 |
| **备选** | 需要更新抓取模型的扩展：E2 堆叠优先抓取 · E4 自动搭积木塔 | 不排期 |

对象是 4 块 3 cm 贴纸方块，分属可回收 / 厨余 / 有害 / 其他四类。B1–B4 对应课程 F1 识别、F2 分拣、F3 看板、F4 兜底；B5 属于 F2 的投放环节。

## ② 不做什么

| 不做项 | 理由 |
|---|---|
| 多机协同 | 需要第二台机械臂，本组只有一台 |
| **机械臂自动翻面（想要但放弃）** | 想让检测器自动覆盖六个面。夹起后倾斜 48°–65° 松手，两次试验均落回原面，第二次落点偏 3.6 cm；改为人工翻面 |
| **压力传感（想要但放弃）** | `Arm_Lib` 只能读角度，没有电流或负载接口；加传感器要改夹爪结构并重新标定。接触与夹持判定改用“指令与回读之差”和夹爪回读角度做代理 |
| 自动避障（自动规划运动轨迹） | 运动走固定分段路径加实测拟合的平台禁入区；不做对任意障碍物的在线轨迹规划 |
| 不同形状物体的抓取优先级 | 对象只有 3 cm 方块；抓取顺序只按距离（E5）决定 |
| 非方块形状的真实垃圾 | 定位依赖“3 cm 立方体、顶面水平”假设，换形状要重做几何与数据集 |
| 深度相机 | 触碰探测测得现有几何模型误差 0.15 cm，够用；加深度相机只增加标定与算力负担 |


## ③ 验收指标

每个功能写明输入、输出、量化指标、风险与兜底。标 **已实测** 的是现状，其余全部是**目标**。

### 基础功能

**B1 YOLO 目标检测**（课程 F1）
- 功能描述：识别桌面上的四类贴纸方块，给出类别、中心与朝向
- 输入：腕部相机 11 个视角的 640×480 图像
- 输出：`scene.json`，每块的类别、地图坐标（cm）、朝向（度）
- 验收指标：mAP@0.5 ≥ 0.90；板上 NPU 单帧 ≤ 50 ms；数据集四类均衡、验证集按整轮留出
- 现状（已实测）：mAP@0.5 **0.952**；单帧 **12.9 ms**；160 真实图 281 框 + 800 合成图 3 138 框；离线 60 块 100% 找到、100% 类别正确
- 风险：暗光下相机掉到约 7 fps，未做系统光照试验；兜底：检测阈值已按暗光样本调整，类别证据不足时输出 `null` 并跳过该块

**B2 精准抓取与定点投放**（课程 F2）
- 功能描述：工作区内任意位置、任意朝向的方块，抓起并放到对应类别的目标位（目标位改为实体容器见 B5）
- 输入：`scene.json`
- 输出：机械臂动作；每步一条事件写入 `log.jsonl`
- 验收指标：工作区为离基座 13–28 cm；连续 10 轮（每轮 4 块）≥ 8 轮四块全中；单块 ≤ 30 s，整轮 ≤ 120 s；投放落点距目标中心 ≤ 1 cm
- 现状（已实测）：最好一轮 **4/4**，累计 18/22，**样本不足**；单块中位 **22 s**，整轮 **99 s**；落点偏差 0.2–0.8 cm
- 风险与兜底：见 ⑤ 风险 1、2

**B3 Web 前端运行日志**（课程 F3）
- 功能描述：网页实时展示分拣作业的全量事件与统计
- 输入：`log.jsonl` 事件流
- 输出：4 个页面：实时状态、分拣记录、统计汇总、异常日志
- 验收指标：事件写入到页面展示 ≤ 1 s；每条记录含时间、类别、来源坐标、目标容器、耗时、结果 6 项；事件无丢失（页面条数 = 日志行数）
- 现状：未开始；字段已在 `log.jsonl` 中
- 风险：板卡时钟比开发机快 8 小时，跨设备测延迟会出错；兜底：延迟用同一设备时钟测量，上板前校正时区

**B4 兜底机制**（课程 F4）
- 功能描述：识别、抓取、投放、路径四类失败各有处理，不需要人工介入
- 输入：夹爪与关节回读、检测票数、运动异常
- 输出：重试、放回原位、退回观察位或跳过，并记日志
- 验收指标：连续 10 轮无需人工干预；单次失败处理 ≤ 5 s；四类失败各至少一条处理路径
- 现状：7 条失败路径已实现并有测试，未按此口径测量
- 风险：未覆盖的异常冲出整轮；兜底：最外层统一捕获，重新使能并退回观察位

**B5 实体容器投放**
- 功能描述：四类各一个真实筐，方块投入对应筐内，替代现在的地图码位
- 输入：`scene.json`、配置中的 4 个容器位置
- 输出：方块落入对应容器；`log.jsonl` 的 `bin` 记容器号
- 验收指标：容器开口内径 ≥ 8 cm、沿离基座约 21 cm 的圆弧摆放；连续 10 轮（每轮 4 块）≥ 8 轮四块全部落入正确容器；投放不碰倒、不推移容器（10 轮内 0 次）；容器壁纳入禁入区模型
- 现状：未到货；选型约束见[实体容器选型约束](12-实体容器选型约束.md)
- 风险：不透明高壁容器会挡住落入的方块，重新扫描无法核对落点；兜底：选壁高 ≤ 4 cm 或透明容器，否则改用夹爪回读加投放计数间接核对。容器未按期到货时，先用同尺寸纸盒完成标定与联调

| **E2 堆叠物体优先抓取** | 备选 | 扫描图像 | 层级判断；先抓顶层 | 两层堆叠 10 次，先抓顶层 ≥ 8 次，下层未被碰倒 ≥ 8 次 | 定位假设顶面在 3 cm 高度，堆叠时顶面在 6 cm；兜底：增加 6 cm 顶面平面的正射图，判不准时下探触碰确认高度 |

| **E7 语音控制** | 排期内 | 麦克风音频 | 启动分拣、跳舞、停止；完成后语音播报 | 3 条指令在安静环境识别率 ≥ 80%；指令到动作 ≤ 2 s | 课程资料描述有 USB 音频模块，**本机未实测**；舵机噪声干扰识别；兜底：机械臂静止时才收音，无音频硬件时改由开发机收音后经网页接口下发 |

## ④ 接口契约

感知、执行、前端三个模块通过文件交换数据。前三张表是代码中已在用的结构，第四张是为 Web 控制新增的**拟定**接口。

**感知 → 执行：`scene.json`**（每轮扫描一份）

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `registration.map_origin_base_cm` | `[float × 3]` | 厘米 | 地图原点在基座坐标系；**z 不采用**，桌面高度用触碰标定值 |
| `registration.yaw_deg` | `float` | 度 | 地图相对基座的偏航 |
| `cubes[].map_cm` | `[float × 2]` | 厘米 | 块中心，地图坐标系 |
| `cubes[].yaw_deg` | `float` | 度 | 块绕 z 轴转角，模 90° |
| `cubes[].category` | `str` 或 `null` | — | `recyclable` / `kitchen` / `hazardous` / `other`；`null` 表示证据不足，E6 据此判未知 |
| `cubes[].detector.votes` | `{str: float}` | — | 各类别置信度之和 |
| `cubes[].detector.approx` | `bool` | — | 检测框被画面裁切，位置仅为近似 |

**执行内部：`plan.json`**（每次抓取一份）

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `tip_target_cm` | `[float × 2]` | 厘米 | 指尖目标，已含张开夹爪的 1 cm 外移补偿 |
| `block_centre_z_cm` | `float` | 厘米 | 闭合高度，基座坐标系 |
| `pitch` / `j5` | `int` | 度 | 末端俯角 130–170 / 腕部旋转 90–180 |
| `aligned` | `bool` | — | 手指能否与块面平行；`false` 为角上夹持 |

**执行 → 前端：`log.jsonl`**（每行一个事件）

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `t` | `float` | 秒（epoch） | 写入方时钟，见风险 3 |
| `event` | `str` | — | 已有：`pipeline_start` `gripped` `put` `pipeline_sorted` `pipeline_missed` `pipeline_skip` `pipeline_end` 等；拟新增：`mode_changed` `unknown_object` `bin_full` `stall` `interaction` |
| `cube` | `[float × 2]` | 厘米 | 来源位置，地图坐标系 |
| `category` / `bin` | `str` | — | 四类之一 / 目标容器编号 |
| `seconds` | `int` | 秒 | 该块耗时 |
| `reason` | `str` | — | 跳过或失败原因 |
| `grip.readback` | `int` | 度 | ≈129 面对面夹住、≈116 对角夹持、132 夹空、29 未动作 |
| `image` | `str` | — | 拟新增：现场图片相对路径，E6 告警时必填 |

**前端 / 语音 / 手势 → 执行：控制指令**（拟定，HTTP POST 的 JSON）

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `cmd` | `str` | — | `start` `stop` `set_mode` `run_preset` `set_joints` `move_to` `unlock_bin` |
| `mode` | `str` | — | `manual` / `preset` / `auto`，仅 `set_mode` |
| `preset` | `str` | — | `dance` / `stack` / `carry`，仅 `run_preset` |
| `joints_deg` | `[int × 6]` | 度 | 六个舵机目标角，仅 `set_joints`；后端按软限位与禁入区校验 |
| `target_cm` | `[float × 3]` | 厘米 | 基座坐标系目标点，仅 `move_to` |
| `source` | `str` | — | `web` / `mobile` / `voice` / `gesture` / `timer`，写入日志以便追溯 |

实时舵机角度由后端以 ≥ 2 Hz 推送：`joints_deg` `[int × 6]`（度）与 `t`（秒）。

**前端展示只依赖 `log.jsonl`，不依赖机械臂在线**，B3 与 W3 可与硬件开发并行；W1、W2 等下发指令的功能用仓库已有的离线模拟工作台（`src/teleop/`）联调。

## ⑤ 已知风险（兜底机制）

三条都来自实测失败。各功能自身的风险见 ③。

| 最可能卡住的地方 | 证据 | 卡住时的替代方案 |
|---|---|---|
| **1 近端带定位偏差**：地图 y ≤ 13 cm 处横向偏约 2 cm | 一块在 (−1.5, 8.6) 连续两次夹空，而检测器给出 3.4 票、4 视角一致 | 该带抓取前先下探核对顶面高度，不符则重新观察（每块多 10–15 s）；仍不稳则把工作区收缩到 y ≥ 13 cm |
| **2 夹爪舵机忽略大跨度指令** | 22 次动作中 6 次；30° 直接发 133° 时回读停在 29 | 先夹，回读显示未动则小步唤醒后重试，最多 3 次；仍失败则跳过该块并记日志 |
| **3 坐标与时钟的隐性错位** | 桌面高度曾被相机估计覆盖，每次下探高 0.8 cm 造成弹飞；板卡时钟比开发机快 8 小时 | 高度以触碰标定为准，相机只给 x/y，两者差超 1.5 cm 时记日志提示重标；延迟用同一设备时钟测，上板前校正时区 |

范围风险：必做与排期内共 17 项，对 11 周偏多，且每周实机时间有限。排期内各项在第 15 周冻结前未完成的不再追加；E2、E4 为备选，不占排期。

### 协作约定

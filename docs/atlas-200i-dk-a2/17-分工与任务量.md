# 分工与任务量

状态日期 **2026-10-11**。本文把[需求规格](10-需求规格.md)里的 17 项必做与排期内功能分给四个人：**前端组 2 人**（Web、手机端、对外服务）和**硬件组 2 人**（凡是要让机械臂、板卡或外设动起来的事）。它替代需求规格“分工与交付物”一节中 A/B/C/D 的划分；功能编号、验收指标、接口字段和阶段日期都沿用需求规格，不在这里改。

> **2026-10-11 之后已就绪、可以直接用的东西**（人日暂不调整，10.23 验收点按实际消耗修订）：
> - [日志契约 v1](18-日志契约.md)、样例日志（`docs/samples/`）和 `/api/log*` 读取与推送接口：F1-2、F2-1、F2-2 的数据源；阶段一验收点里的“接口定稿”，日志这一项已有初稿，待两组确认。
> - 仿真后端可以一键跑真实分拣流水线并注入夹空（[仿真模块](16-仿真模块.md) §5）：F2-6 的“日志回放与失败注入工具”有了基础，只剩前端侧的回放与其余失败类型。
> - 模型与物块贴面在 Release `assets-v3`，取回步骤见[根 README](../../README.md)。
> - 新发现、归 H1 的一项：物块在地图近端时补拍视角失败的异常未被捕获，整轮中断（见日志契约 §7），并入 H1-7 兜底量化处理。

**任务量是估算，不是实测。** 单位是人日（一人专注做一天），由功能的现状和接口文档里的差距估出来，没有历史工时可对照；第一个验收点（10.23）之后按实际消耗修订一次。姓名待填。

|---|---|---|---|
| **F1** | 前端 | 对外服务 + 电脑端网页的“看”和“控” | 25.5 |

原来 D 的“测试与文档”不再单设一人：**每人写自己功能的测试和文档，验收由另一组的人执行**（见 §4）。

## 4. 两组之间

**接口由谁负责写**（读的一方发现问题找写的一方）：

| 接口 | 写入方 | 读取方 |
|---|---|---|
| `scene.json`、`log.jsonl` 的字段与已有事件（[日志契约](18-日志契约.md)，改动先改 `src/tools/log_contract.py`） | H1 | F1、F2 |
| `stall`、`bin_full`、`interaction` 事件 | H2（格式按 H1 定的写） | F2 |
| 控制指令 JSON 与对外服务 | F1 | H1（执行侧）、H2（语音、手势都经它下发） |
| 容器位置与禁入区参数 | H2 | H1 |
| 仿真后端的 `/api/sim/*` | H1 | F1、F2 |

**验收交叉进行**：前端组验硬件组的功能，硬件组验前端组的功能；按需求规格 ③ 的指标执行，功能负责人在场，每次一条记录（日期、设备、条件、数字、结论）入库。

**实机**：只有 H1、H2 操作机械臂，执行前按[硬件安全边界](../05-板卡连接与硬件实测.md)人工确认周围安全。每周上机前一天，四个人把要在实机上验证的条目交给当周上机的人；每周约 2 小时里，H1 的抓取与投放约占六成，H2 的外设与交互约占四成，前端联调并入其中。

**前端组不等硬件**：全部页面先对[仿真后端](16-仿真模块.md)和已有日志开发。仿真里的 `/api/sim/*` 与 `status.sim` 在实机上不存在，页面要按可选处理。

## 5. 待确认

- 四个人的姓名与对应代号。
- 每人每周能投入的天数：按 10 周、每人每周 2.5–3 人日估，总量刚好够；低于这个数就要砍排期内功能，建议的顺序是 E7 语音、E1 手势、W4 定时。
- 小程序还是手机浏览器：本文按手机浏览器的响应式页面估算（7 人日）；做小程序要另加注册审核与 HTTPS 域名的时间。

## 相机、NPU、运动学链路中的实际约束

- `garbage_identify.py` 使用 `InferSession(0, model_path)`，NPU 前处理在 `npu_utils.py`：letterbox 到 640×640、BGR→RGB、CHW、float16/255，再经 `det_utils.py` NMS。项目需用真实 OM 输入输出核对这一布局。
- [相机校准 Notebook](../../资料/官方资料/Atlas-200I-DK-A2-机械臂/ros2_robot_arm-upstream/ros2_ws/src/dofbot_garbage_yolov5/tools/相机校准.ipynb)、`utils/dofbot_config.py` 与 `config/{XYT_config.txt,dp.bin,offset.txt}` 均已落盘。它们服务于十字框透视变换和固定桌面抓取；上游配置是示例，不是当前设备的有效标定。
- `garbage_identify.py` 将检测框中心按固定经验公式换算为平面 `(x,y)`，再加 `offset.txt` 的偏移送 `trial_service`。它不是带相机内外参、深度和误差估计的通用三维定位。
- `dofbot_server.cpp` 在构造函数中把 URDF 写死为 `/root/ros2_robot_arm/ros2_ws/src/dofbot_moveit/urdf/dofbot.urdf`。`config/server_param.yaml` 虽写有同一路径，当前源码并未读取该参数；部署目录不同就要核对路径。该服务对五个关节做 FK/IK，并在 IK 中使用固定夹爪长度 `0.12 m` 和经验末端姿态公式，不能直接视为当前机械臂的已校准几何。
- `get_pos()` 使用 `msg[name] = (a,b)` 保存目标，同类别出现多个积木会覆盖前一个；多目标自主分拣须改成带目标 ID 的列表/跟踪结构。
- `garbage_identify.py` 在模块导入时初始化 `rclpy`，实例化时创建 `Arm_Device`。后续抽取纯视觉函数时不能直接导入该模块做离线测试，也不能用上游测试脚本替代当前设备安全验收。

## 模型与标签不能混用

官方仓库的两个应用包各有 `model/coco_names.txt`，内容均为 `Fish_bone`、`Newspaper`、`Syringe` **三类**；仓库没有 `.om` 文件，上游 README 要求另下载 `yolov5s_bs1.om`。本地课程流水线的同名 OM 与标签是 `Blue/Green/Red/Yellow` **四类颜色**。两者同名并不能证明模型架构、类别顺序、张量 shape 相同；在板端读取模型元数据和固定样本输出前，不把本地 OM 复制到官方工程模型目录。当前项目四种垃圾图案贴纸又是第三套类别定义，应单独采样、训练与验证。

## 2026-09-24 与当前板卡和实机的核对

- **板上现状**：没有 `/root/ros2_robot_arm`。`/opt/ros/humble` 与 `/usr/lib/libdofbot_kinemarics.so`（2023-05-09）来自出厂镜像，`/root/.ros/log` 中有 2023-05 的 `dofbot_server` 运行日志；`/root/__MACOSX/RobotArm/ros2_dofbot_ws` 只剩 2435 个 AppleDouble `._*` 文件，不是可用工作区；`/home/driver_ws` 是 Yahboom 小车包。板卡无外网，按 README 安装 ROS 依赖须离线传包。
- **关节方向**：上游以“舵机角 − 90°”作为关节角，URDF 中 2–4 号正向使手臂后仰。实机小步测试结果一致：2 号 90→100 时后仰，3 号 90→80 时前折。
- **几何可直接用于 Python**：`dofbot_server` 的 IK 本质是 URDF 上的 KDL 求解，外加固定夹爪长 0.12 m 和经验俯仰 `Roll = 2.5·y·100 − 207.5`。项目以相同几何写了不依赖 ROS 的 [`src/spatial/dofbot_kinematics.py`](../../src/spatial/dofbot_kinematics.py)（平面正逆解，带软限位搜索）。用它回算板上旧脚本手调的抓放点，夹爪尖高度在 −0.6～3.6 cm 之间；四角约为 (±13.5, 28.9) 与 (±13.7, 13.8) cm，中心为 (0, 22.6) cm，即“四角加中心”的地图布局。这说明 URDF 几何与舵机换算在这台臂上大体成立，但 z = 0 与桌面的实际高差及毫米级误差仍须实测。
- **观察位**：上游用 `[90,130,0,0,90,30]` 观察；本机以软限位替代端点，使用 `observe_v0 = [90,125,5,5]`。FK 算得腕部约 17.6 cm 高、末端俯角 45°，对准底座前方约 24 cm 处，与板载画面中物块位置吻合。
- **不直接复用的部分**：抓放过程用单舵机写 1 号和 6 号（本板 1–5 号单写不生效）；5 号固定 265；`sleep` 代替到位确认；像素→平面用固定经验常数和上游 `offset.txt`。这些在本项目中分别由批量写、软限位、回读校验和现场标定替代。

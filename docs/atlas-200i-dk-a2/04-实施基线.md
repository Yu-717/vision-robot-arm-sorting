# 开发与验证基线

这份计划根据用户在前次讨论（本机 Codex 对话，仓库外不可访问）确认的“14 周、通常每周约 2 小时实物验证、基础四贴纸积木垃圾分类”制定。指标是建议验收方法，尚未由团队或课程教师确认；实际目标按积木尺寸、夹爪余量与现场测试反推。

## 第一个可交付闭环

```text
摄像头录制/取帧 → 四贴纸检测与类别置信度
→ 桌面平面定位 + 有效区/可达性检查
→ 单一受控机械臂任务 → 夹取、抬升、分类投放
→ 重新观察与关节反馈 → 成功/失败证据和日志
```

最先要解决的是**识别是否针对当前贴纸、定位是否达到夹爪容差、命令是否真的让关节到位、目标是否真的离开原位并进入容器**。发送成功、定时 `sleep` 结束和识别框消失都不能单独证明完整抓放成功。

## 工作包与现场证据

| 周期建议 | 离线交付 | 每周现场约 2 小时重点 |
|---|---|---|
| 1–2 周 | 设备/版本清单、四贴纸类别表、相机帧录制、官方/课程基线复现清单 | 只读自检；板端运行旧 OM，记录输入输出、延迟及样本图；复查单写异常 |
| 3–4 周 | 相机与桌面标定程序、坐标和误差日志、受控关节动作接口 | 测工作区点位、夹爪开合和小步定位；固定点抓取 |
| 5–6 周 | 单积木随机位置抓放、四类投放、错误状态 | 网格点实测定位误差、抓取和投放；若闭环不稳，暂停扩展修基础 |
| 7–9 周 | 多目标检测/队列、未知类拒绝、重新观察 | 2–4 积木及空白/遮挡贴纸测试；查重复抓取和错误分类 |
| 10–11 周 | 抓取视觉验证、有限重试、失败记录 | 故意造成漏抓/定位偏差，验证停止、重试上限与人工介入 |
| 12–14 周 | 统计界面、鲁棒性实验、报告和演示回放 | 光照、旋转、遮挡与完整流程复测；冻结环境和配置 |

每次现场测试提前准备版本号、设备编号、标定 ID、物体位置、测试次数和失败判定；带回原始帧、预测结果、命令、回读和视频。2 小时结束前备份数据。离线可完成数据标注、模型训练、推理后处理、坐标算法、任务状态机和界面；设备时间集中用于相机、NPU、关节、标定及抓放实测。

## 基本验收记录

至少分开统计：四类贴纸的检测准确/漏检/误检，NPU 推理延迟，桌面各点位定位误差，首次抓取成功率、重试后的最终成功率、投放成功率和连续运行中断次数。样本量、置信区间与环境条件必须和结果一起记录；前次对话提出的“≥95%”等值只是目标建议，不能写成已有性能。

状态机与坐标契约可从[已有方案](../03-空间定位与任务组合.md)开始，但正式实现前需确认相机安装位、关节轴和零位、工具中心点、夹爪范围、标定失效条件、动作取消的实际语义。`Arm_Action_Mode(0)` 不能未经实测就标为急停；任何运动脚本先走限幅和人工监督。

## 下一次开发的开工顺序

1. 使用[已归档的官方固定源码版本](06-官方源码导入审计.md)，核对 NOTICE、缺失的 OM 模型、硬编码 URDF 路径、板端依赖与设备标定。课程平台目前没有新增指导页面，不以此阻塞开发。
2. 只读记录当前板卡 CANN、ROS 2、`ais_bench`、OpenCV、Python、摄像头设备和 OM 输入输出；对比官方工程版本。
3. 收集当前四贴纸的图像、标签和容器映射；先离线验证，再训练/转换并上板。
4. 现场确认相机、机械臂、桌面几何，按设备保存标定结果；抽取纯感知与受控执行模块。
5. 固定点抓取后再随机位置抓取；每次扩大范围都保留误差和失败证据。

## 第二阶段（2026-09-26 与用户确认）

第一阶段闭环已在实机跑通，证据见[硬件实测](../05-板卡连接与硬件实测.md)末节。第二阶段的方向：推理必须在板上 NPU 运行；投放改用实体容器；训练更多种类的真实垃圾；识别和抓取不再假设物体是 3 cm 方块，改用多视角几何重建。建议顺序如下，每一步都用可量化的证据验收：

| 步骤 | 内容 | 验收证据 |
|---|---|---|
| 0 | v3 转成 `.om`，上板推理 | 板上延迟；与 ONNX 在同一批图上的输出对照 |
| 1 | 多轮随机摆放统计；失败重试、放后核对、格子被占时先移走占位块 | 首次成功率、最终成功率、中断次数，附样本量 |
| 2 | 实体容器投放 | 容器壁进入禁入区；松手高度；放后看容器内部确认 |
| 3 | 可见外壳重建：先在 3 cm 方块上验证（真值已知），再换不同尺寸的长方体和圆柱 | 中心、高度、朝向误差，与方块模板法对比 |
| 4 | 按外壳规划抓取，按不确定性补拍 | 先实测夹爪角度与开口宽度的关系；补拍前后的误差和抓取成功率 |
| 5 | 真实小垃圾：采集（外壳投影自动生成框）、训练、拒绝未知类 | 分类别统计识别、抓取和投放成功率 |

**方法选择**：深度用多视角几何求，不用单目深度网络。每个视角的相机位姿由地图码 PnP 解出，比舵机正解更准。体素求交在板上 CPU 就能完成，NPU 只负责检测或分割。

**已知限制**：
- 透明、反光的物体，轮廓不可靠。
- 扁平物体几乎没有高度，外壳帮不上忙。
- 物体大小受夹爪开口、可达距离（约 13–28 cm）和塑料齿轮舵机的负载限制。

ADR-0003 不建议深度相机，前提是“物块高度已知”，这个前提已不再成立。几何方法遇到难以处理的物体时，重新评估深度相机或固定俯视相机。

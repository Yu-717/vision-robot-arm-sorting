## 资料分层

- `资料/原始解压/`：保留原始包目录；空目录也是原始证据。
- `资料/展开资源/`：内层ZIP展开后的模型、Notebook、STL、样本及安装程序。
- `资料/课程说明/`：课程采集归档和派生 HTML/TXT/代码块。原始 JSON 是重建离线页的输入。
- `scripts/organize_stage2.py`：资料生成脚本，执行时可能访问图片/视频源站；不是机械臂应用。
- `scripts/inventory_resources.py`：本地只读盘点脚本，输出到 `docs/inventory/`，不导入或执行机械臂代码。
- `docs/`：本次整理的事实清单、分析和方案。
- `.codegraph/`：按用户授权建立的索引缓存。首轮18个文件、113个节点、201条边；新增文件后这些统计会变化。Notebook细节另外记录在代码结构JSON中，不将自动推断的跨片段调用关系当成实际Python导入关系。

维护盘点：在项目根目录运行 `python scripts/inventory_resources.py`。课程说明生成需要当前已安装的 `beautifulsoup4`；没有建立机器人应用依赖锁文件。

## 首先解决的五件事

1. 继续补齐当前板卡的 CANN/ais_bench 与模型输入输出实测；Arm_Lib 0.0.5、I²C-7/0x15 和硬件版本 0.20 已确认。
2. 排查 `Arm_serial_servo_write` 对 1–5 号不生效的问题；批量接口已通过，限位按课程目录固定为 1–4、6 号 0–180°，5 号 90–270°。
3. 确认摄像头固定在外部还是安装在机械臂上，完成内参及相机到机械臂基座的标定。
4. 先做桌面平面上可度量的目标定位、可达性检查和单物体抓放，再扩大到有高度变化的三维场景。
5. 将检测、定位、抓取和手势/人脸触发拆开，通过同一个执行模块组合；识别结果本身不能作为抓取完成证据。

## 验证范围

静态阶段读取了 4 个 Notebook、基础课程代码块、运动学头文件及动态库文件头，并生成文件索引和关键代码/模型 SHA-256。硬件阶段已加载板端 Arm_Lib、采集摄像头帧并执行限幅的小步舵机测试；没有运行课程 Notebook、跳舞、抓放、OM/PTH 模型或碰撞未知的大范围动作。STL 单位和关节连接、ONNX/OM 张量规格仍未实测。
